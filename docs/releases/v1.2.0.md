# SnapStudio 1.2.0

Capture an ExactFrame region directly into SnapStudio, ready to annotate, copy, or export.

## Download and start

Download [the Windows x64 portable ZIP](https://github.com/MaxAkbar/SnapStudio/releases/download/v1.2.0/SnapStudio-1.2.0-win-x64-portable.zip), extract the **entire archive**, and open **SnapStudio.App.exe**. Requires Windows 11 x64. The ZIP includes .NET and the Windows App SDK runtime; Help and the SVG designer require the Microsoft Edge WebView2 Runtime.

For the new connection, install [ExactFrame 2.2.0 or newer](https://github.com/MaxAkbar/ExactFrame/releases/tag/v2.2.0). In ExactFrame, choose the main frame or an additional guide, click **Capture in SnapStudio**, and choose **SnapStudio.App.exe** once. Finish SnapStudio's first-run setup before capturing. See the [setup guide](https://github.com/MaxAkbar/SnapStudio/blob/v1.2.0/docs/exactframe-integration.md).

## What's new since 1.1.0

- Capture ExactFrame's main frame or a nested guide at its exact physical screen dimensions, without redrawing the region or scaling it to a planned recording output size.
- Start SnapStudio automatically when needed and open the captured image in its local library for editing.
- Hide both app windows and ExactFrame's HUD and guides during capture. Restore the overlays afterward while keeping SnapStudio in front after success.
- Report busy dialogs, invalid regions, unsupported older builds, timeouts, and disconnections. The bounded local connection checks request versions and correlation IDs and cancels capture when the client disconnects.
- Updated README and offline Help with compatible releases and setup steps. The README also includes an animated walkthrough of the real editor.

The integration exchanges bounds and status over a current-user-only, session-specific Windows named pipe. SnapStudio captures and stores the image locally. No images or databases are shared between the apps, no online requests are made by this connection, and the clipboard stays unchanged.

## Compatibility and limits

- Use SnapStudio **1.2.0+** with ExactFrame **2.2.0+**. Keep `SnapStudio.integration.json` with the executable and its other files. Close an older running copy before updating.
- The entire frame must fit on one connected display. Each side must be 4–20,000 pixels, with at most 40 million pixels total. Negative desktop coordinates are supported by the protocol.
- The document format remains schema 12, as in 1.1. Existing captures and settings remain in your local profile.
- The portable download is unsigned. The additional `SnapStudio_1.2.0.0_x64.msix` is an unsigned, framework-dependent evaluation package requiring trusted signing and matching runtimes; use the portable ZIP for normal use.
- OCR, scrolling capture, and screen recording remain experimental and disabled by default. Store certification and signed distribution remain separate work.
- Automated checks cover validation, transport limits, malformed requests, disconnect cancellation, and monitor containment. Local x64 integration checks covered exact main/nested frame captures at 175% scaling, app startup/reuse, focus, and busy-dialog recovery. Other native monitor layouts, negative-coordinate displays, ARM64, and MSIX activation remain unverified for this integration.

`SHA256SUMS.txt` verifies the packages and attached validation reports. See [all changes since 1.1.0](https://github.com/MaxAkbar/SnapStudio/compare/v1.1.0...v1.2.0).
